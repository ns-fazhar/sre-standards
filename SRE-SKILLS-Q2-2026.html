SRE Standards - Q2 2026 Project

Owner: SRE Team
Date: April 2026

Use Case

Developers commit code without knowing they're missing critical reliability, observability, and operational patterns - these gaps surface during reviews or production incidents. SRE Standards provides pre-commit feedback via automated skills that scan code and identify what's missing before commit, eliminating costly late discovery and embedding SRE expertise directly into development workflow.

Q2 2026 Acceptance Criteria

Develop 4 production-ready skill categories:

  • SRE Checks - Scan for reliability/resilience patterns (circuit breakers, retries, timeouts)
  • Operability - Dataflow validations, generate runbooks/playbooks for troubleshooting
  • Observability - Scan for metrics instrumentation, suggest dashboards and alerts
  • NPI - New feature introduction, validate branch-based feature releases

Skills invoked via Claude Code (/skill-name) in local developer environment or GitHub Actions on PR, with bash scripts as fallback when Claude unavailable.

Success: Complete skill development, pilot with 2-3 services to validate effectiveness and gather feedback, then sell program across organization for broader adoption.

Note: Skills invoked from local developer environment (during coding) or GitHub Actions (on PR) - immediate feedback before code commit.

PRR Automation Path: With these skills in place, they will partially cover Production Readiness Review (PRR) requirements by automatically validating reliability, observability, and operational patterns. Q3 2026 goal is to evaluate whether we can automate most of the PRR data collection process, reducing manual PRR overhead.
